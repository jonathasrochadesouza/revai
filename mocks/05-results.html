Signing key read from environment without null validation

Critical CWE-347 ai + semgrep

Replacing the hardcoded secret was the right call, but System.getenv("JWT_KEY") returns null when the variable is absent. signWith will then throw at request time rather than at startup, turning a configuration mistake into a runtime 500 on every login.

Why this matters

Fail fast, not at request time. Objects.requireNonNull turns a missing environment variable into a clear startup error instead of an opaque NullPointerException on the first login attempt. Two additional improvements are folded in:

  • The magic number 86400000 becomes TOKEN_TTL_MS via Duration.ofDays(1) — self-documenting and unit-safe.
  • The stale // TODO: rotate before release comment is removed since the key now comes from configuration.

Consider moving this to Spring's @Value with a @PostConstruct assertion so the whole application context refuses to start when the secret is missing.
